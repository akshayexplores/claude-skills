# FastrBuild Design Guide

Use this skill for **FastrBuild-branded visual work**. It does not automatically apply to Akshay's personal brand, Vajra, Brandframe, or a client's identity merely because FastrBuild made the work.

The approved direction is **Sea glass**: a refined `fastrBuild.` wordmark, Newsreader display type, Plus Jakarta Sans body type, deep teal ink, mint paper, seafoam fields, and restrained peach accents. The look should feel human, optimistic, calm, and operationally credible. The public FastrBuild site adopted this direction on 27 September 2026; the source design tokens and examples are in [references/visual-system.md](references/visual-system.md). Read that reference when creating or reviewing a visual artifact.

## Apply the identity

- Set **FastrBuild** in prose. Use **`fastrBuild.`** only as the visual wordmark: lowercase `fastr`, capital `B`, final accent period. There is no approved standalone icon.
- Use Newsreader for expressive headlines and Plus Jakarta Sans for body text, labels, controls, and the wordmark. Treat the exact website layout as an example, not a template for every medium.
- Lead with one clear idea and generous space. Use color fields, type hierarchy, fine rules, and small human details to create warmth. Avoid filling a surface with repeated cards, decorative symbols, or dense simultaneous copy.
- If imagery helps, favor believable human work and tactile materials. The live website uses **one illustrative hero scene**; that is not a mandate to repeat the image elsewhere. Clearly label generated scenes so they cannot be mistaken for staff, clients, or actual work.
- Keep interactions subtle and purposeful; support keyboard focus and reduced motion. Check text contrast, responsive behavior, and readability in the actual medium.

## Resolve scope and authority

- Preserve an existing artifact's factual copy and links unless the user authorizes a content change. For dense content, first improve hierarchy or disclosure; do not silently remove details.
- For positioning, offers, claims, proof, and tone, load `$fastrbuild-context` when available. This skill supplies **visual identity**, not approval for new public claims.
- Follow a newer explicit FastrBuild design decision if it supersedes this guide, and note that the guide may need updating. Older local notes that specify **signal lime** or **Instrument Serif** predate the approved Sea glass and Newsreader direction.
- The recent idea to simplify the three offer cards with expandable details is **an exploration**, not part of the shipped identity. Do not treat it as an approved component or change the live site because of this skill.
- Installing or invoking this skill does not authorize publishing, changing a live system, or contacting anyone.
